## 一、游戏架构概览

### 1.1 引擎与技术栈

| 项目 | 详情 |
|------|------|
| **游戏引擎** | cocos2d-x（C++ 开发） |
| **可执行文件** | `SmallWorld.exe` |
| **UI 描述格式** | `.ccbi`（CocosBuilder 二进制文件） |
| **精灵图集** | `.plist`（Cocos2d 纹理图集配置） |

### 1.2 关键依赖库

- `WebKit.dll` / `JavaScriptCore.dll` — 内嵌浏览器，用于渲染规则书（Compendium）和鸣谢页面

- `glew32.dll` / `cairo.dll` — 图形渲染
- `steam_api.dll` — Steam 集成

## 二、本地化系统分析

### 2.1 目录结构

游戏采用 Apple 风格的 `.lproj` 目录组织多语言资源：

```
Resources/
├── en.lproj/          英语
├── fr.lproj/          法语
├── de.lproj/          德语
├── es.lproj/          西班牙语
├── it.lproj/          意大利语
├── ja.lproj/          日语
├── nl.lproj/          荷兰语
├── compendium/        规则书（HTML）
│   ├── en/  en-short/
│   ├── ja/  ja-short/
│   └── ...
└── fonts/             字体文件
```

**当前不包含中文（zh）语言包。**

### 2.2 文本资源

每个 `.lproj` 目录包含以下文本文件：

| 文件 | 字符串数量 | 内容 |
|------|-----------|------|
| `localizedStrings.xml` | 281 | 主 UI 文本、种族/能力名称、消息提示 |
| `tooltips.xml` | 77 | 工具提示 |
| `errorMessages.xml` | 28 | 错误信息 |
| `ssoStrings.xml` | 91 | 登录/认证相关 |
| `Localizable.strings` | 9 | 推送通知（Apple .strings 格式） |
| **合计** | **~486** | |

**文本格式示例**（`localizedStrings.xml`）：
```xml
<string key="swdm::AmazonRace_Name">Amazons</string>
<string key="MessageBox_OK">OK</string>
```

文本采用 **key-value 键值对** 方式加载，无硬编码，翻译难度低。

### 2.3 图片资源

每个 `.lproj` 目录包含 `common/` 和 `common-hd/` 两个子目录，存放带文字的本地化图片：

- **180 张（common）+ 180 张（common-hd）= 360 张图片**
- 包括按钮文字、标题、种族/能力图标文字等
- 意大利语包额外提供 `images.xml`（翻译参考用，非运行时使用）

### 2.4 规则书（Compendium）

规则书采用 HTML 格式，通过内嵌 WebKit 渲染：

- **完整版本**：107 个 HTML 文件（种族、能力、规则、指南）
- **简版**：71 个 HTML 文件
- 使用 jQuery 1.9.1 + CSS 样式

### 2.5 鸣谢页面

- `Resources/credits/credits.html` — 单文件 HTML

## 三、字体支持分析

### 3.1 字体文件

| 文件 | 实际字体 | 大小 |
|------|---------|------|
| `arialmt.ttf` | Noto Sans Medium | 1.15 MB |
| `futura-medium.ttf` | 与 arialmt.ttf 完全相同 | 1.15 MB |
| `futura-condensedmedium.ttf` | Noto Sans Condensed Medium | 1.15 MB |

### 3.2 中文字符支持

- **总字形数**：6,588
- **CJK 统一汉字**：**5,932 个**（U+4E00–U+9FFF 范围）
- **平假名**：174 个
- **片假名**：180 个
- **韩文**：0 个

**结论**：游戏内置字体已支持常用中文字符（覆盖 GB2312 约 88% 的 6,763 字），**无需替换字体即可显示中文**。

### 3.3 文本渲染方式

UI 文本通过 cocos2d-x 的 `CCLabelTTF` 渲染，使用 TrueType 字体，支持动态生成中文字形。

## 四、语言切换机制

### 4.1 语言检测方式

游戏通过以下三种方式确定当前语言：

1. **系统语言**：调用 Windows API `GetUserDefaultUILanguage()`
2. **命令行参数**：`SmallWorld.exe language=ja`
3. **游戏内设置**

### 4.2 支持的语言列表

可执行文件中硬编码的支持语言为：
```
de | en | es | fr | ja | nl
```
（意大利语 `it` 虽存在语言包，但不在此列表中，可能为后续补丁添加）

### 4.3 语言到资源目录的映射

游戏将 `LanguageType` 枚举映射为 2 字母语言代码，然后加载 `<code>.lproj/` 目录。若系统语言不在支持列表中，则**回退到英语（en.lproj）**。

**关键问题**：中文系统语言会被识别但不在支持列表中，因此会回退到英语，**无法直接加载中文语言包**。

### 4.4 在线相关

- 语言代码会发送到 Days of Wonder 在线服务器
- `RulesLanguage` 字段决定加载哪个语言的规则书 HTML
- 在线游戏有版本检查

## 五、汉化方案评估

### 5.1 方案对比

| 方案 | 描述 | 可行性 | 风险 | 可逆性 |
|------|------|--------|------|--------|
| **方案 A：替换日语包** | 用中文翻译覆盖 `ja.lproj`，通过 `language=ja` 启动 | ★★★★★ | 低 | 完全可逆 |
| **方案 B：替换英语包** | 用中文翻译覆盖 `en.lproj`，默认启动即中文 | ★★★★ | 低 | 可逆 |
| **方案 C：新增 zh 语言包** | 创建 `zh.lproj`，修改可执行文件识别中文 | ★★ | 高（可能触发 Steam 校验/版本检查） | 较难 |
| **方案 D：DLL 代理注入** | 通过代理 DLL 拦截语言检测函数 | ★★★ | 中 | 可逆 |

### 5.2 推荐方案：A（替换日语包 + 命令行启动）

**理由**：
1. 日语包已使用 CJK 字体，中文显示无障碍
2. 无需修改可执行文件，不触发 Steam 完整性校验
3. 完全可逆——删除中文文件即可恢复
4. 可通过启动参数灵活切换

**实现步骤**：
1. 备份原始 `ja.lproj` 目录和 `compendium/ja/`、`compendium/ja-short/`
2. 将中文翻译写入 `ja.lproj/` 下的所有 XML/strings 文件
3. 将中文规则书 HTML 写入 `compendium/ja/` 和 `compendium/ja-short/`
4. 制作 360 张中文本地化图片（或采用文本覆盖方案）
5. 提供启动器批处理文件：
   - `启动中文.bat`：`SmallWorld.exe language=ja`
   - `启动原版.bat`：正常启动（使用系统语言）

### 5.3 无损启停方案

**目录结构设计**：
```
SmallWorld2/
├── Resources/
│   ├── ja.lproj/              ← 当前生效（中文或原版）
│   ├── ja.lproj.original/     ← 原版日语备份
│   └── ja.lproj.chinese/      ← 中文翻译
├── 启用中文.bat               ← 符号链接/复制切换到中文
├── 恢复原版.bat               ← 恢复原版日语
└── docs/                      ← 本文档
```

**切换脚本逻辑**：
```
启用中文.bat:
  1. 备份当前 ja.lproj（如果未备份）
  2. 删除 ja.lproj
  3. 复制 ja.lproj.chinese 为 ja.lproj
  4. 启动游戏：SmallWorld.exe language=ja

恢复原版.bat:
  1. 删除 ja.lproj
  2. 复制 ja.lproj.original 为 ja.lproj
  3. 正常启动游戏
```

## 七、潜在风险与注意事项

### 7.1 在线功能风险
- 使用 `ja` 语言代码可能影响在线匹配（系统可能将你与日语玩家匹配）
- 在线版本检查不会因语言包修改而失败（未修改可执行文件）
- 建议：在线对战时使用原版，单机/本地对战时使用中文

### 7.2 字体限制
- 5,932 个汉字可覆盖绝大多数常用文本
- 生僻字可能显示为方框，需提前测试
- 种族/能力名称中如含生僻字，可考虑用同音字替代

### 7.3 图片本地化
- 360 张图片工作量大，可考虑：
  - **方案一**：仅翻译关键按钮/标题图片（约 50 张核心 UI）
  - **方案二**：探索是否可通过 `images.xml` 机制用文本覆盖图片（需进一步验证运行时是否支持）
  - **方案三**：全部重制（最完整但耗时）

### 7.4 Steam 完整性校验
- 不修改可执行文件，仅替换资源文件，**不会触发 Steam 文件校验失败**
- 但 Steam 更新可能覆盖修改的文件，需重新应用补丁

## 八、结论

### 总体可行性：★★★★☆（高）

**有利因素**：
1. ✅ 文本资源全部外置（XML/strings），无硬编码
2. ✅ 内置字体支持 5,932 个汉字，无需替换字体
3. ✅ 规则书为 HTML 格式，翻译方便
4. ✅ 支持命令行语言参数，可灵活切换
5. ✅ 无需修改可执行文件，安全可逆

**不利因素**：
1. ⚠️ 游戏不原生支持中文，需借用日语语言包
2. ⚠️ 360 张本地化图片工作量大
3. ⚠️ 在线对战时语言代码为日语，可能影响匹配

**建议**：采用**方案 A（替换日语包）**，优先完成文本翻译和核心图片，规则书可分步翻译。提供一键启停脚本，实现无损切换。
